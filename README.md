# nfl-football

Pulls the week's NFL schedule with win odds, aggregates each team's news, and
uses a local LLM to argue who wins. Every data source is free and keyless.

See [plan.md](plan.md) for the staged build log, measurements and design
decisions.

## Setup

```bash
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

An [Ollama](https://ollama.com) host with `qwen2.5:7b` is required. Point at it
with `OLLAMA_URL` (default `http://192.168.2.167:11434`).

## Usage

```bash
source .venv/bin/activate
python -m nfl_football
```

Writes `report.html` and prints a markdown report to stdout.

| Flag | Effect |
|---|---|
| `--season 2026 --week 1` | pick a week (defaults to the current one, resolved from ESPN) |
| `--game DEN@KC` | one matchup only |
| `--refresh` | bypass every cache and regenerate |
| `--no-llm` | odds and news only; skip briefs and theses |
| `--html PATH` / `--no-html` | where to write the HTML report, or skip it |
| `--quiet` / `--no-sources` | suppress stdout / omit source links |
| `--email` | email the report |
| `--email-to ADDR` | recipient (default `kevin.wood75@gmail.com`) |
| `--email-dry-run [PATH]` | write the message to a `.eml` instead of sending |
| `--check-email` | report SMTP configuration and exit |

Kickoff times are shown in **America/Toronto** (EDT/EST). Override with
`NFL_TZ=America/Los_Angeles` in `.env` or the environment.

## Email

Credentials live in a `.env` file in the project root, which is gitignored:

```bash
cp .env.example .env
chmod 600 .env
```

Then edit `.env`:

```ini
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=you@gmail.com
SMTP_PASSWORD=xxxx xxxx xxxx xxxx
#SMTP_FROM=you@gmail.com     # optional, defaults to SMTP_USER
```

**Gmail requires an App Password**, not your account password: enable 2FA, then
generate one at <https://myaccount.google.com/apppasswords>. A normal password
returns `535 authentication failed`, and the error says so.

Confirm the setup without sending anything:

```bash
python -m nfl_football --check-email
```

It prints the host, user and recipient, reports the password only as
`***set***`, and warns if `.env` is readable by other users.

Then check the message itself before sending anything real:

```bash
python -m nfl_football --email-dry-run report.eml
```

Nothing is ever sent without an explicit `--email`.

The email body uses a separate, mail-safe template — table layout, inlined
styles, no CSS variables or flexbox — because Gmail and Outlook support none of
what the standalone report relies on. It also stays under Gmail's ~102 KB
clipping limit (82 KB for a typical week) and drops per-game injuries and
"news vs market" automatically if a week would ever exceed it. The full
`report.html`, with every source link, is attached to the message.

Notes on precedence and safety:

- An exported environment variable **overrides** `.env`, so a one-off run can
  use different settings without editing the file.
- `NFL_ENV_FILE=/path/to/other.env` points at a different file.
- The password is never logged, printed or written to disk by this project —
  `SmtpConfig.__repr__` redacts it, and there is a test asserting that.
- `.env` is in `.gitignore`; `.env.example` holds placeholders only.

## How it works

1. **Schedule and odds** — ESPN scoreboard, with nflverse as fallback.
2. **Win probability** — computed in Python: American moneylines → implied →
   de-vigged. Never calculated by the model.
3. **Team briefs** — one LLM call per team compresses ~40 headlines into
   storylines and momentum. Injuries pass through from ESPN untouched.
4. **Game theses** — two calls per game. The first sees *only* the news and
   commits to a lean; the second sees the market plus its own lean and picks.
5. **Report** — markdown and a self-contained HTML file showing news lean,
   market favourite and final pick side by side.

The model makes the final call and may pick against the market; those games are
flagged as upset calls. Win probabilities come from the odds, always.

## Tests

```bash
source .venv/bin/activate && python -m unittest discover -s tests -t .
```

231 tests, all offline — no host or network required. Re-derive the spread
calibration with `python -m tests.calibrate_spread`.

## Caching

Everything is cached in `.cache/nfl.db` (SQLite): HTTP responses by URL, LLM
responses content-addressed on the prompt hash. A warm rerun costs seconds.
Because the thesis prompt embeds the betting line, **a line move invalidates
those responses** — correct, but it means reruns are only free inside ESPN's
15-minute odds TTL.

Picks are generated by a small local language model. Not betting advice.
